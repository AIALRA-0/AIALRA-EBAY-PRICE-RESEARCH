# eBay 商品查价与风险研究

## 这个 Skill 负责什么

用户提出 eBay 查价、最低价、商品链接核验、卖家风险或购买建议时使用本 Skill

最终结果必须来自当前 eBay 搜索结果和商品详情，不得使用记忆价格、搜索引擎摘要或第三方比价摘要代替

本 Skill 只读取公开商品信息，不执行购买、出价、议价、联系、关注或其他账户写入

## 一次合格研究必须完成什么

- 先验证当前后端能够真正进入搜索结果页，打开首页不算通过
- 至少执行三轮搜索，每轮使用不同查询词或排序方式
- 保存每轮观察，再按 eBay 数字商品编号去重
- 先排除空盒、单独配件、坏件、维修、服务和预售等明显错配
- 打开入围商品详情，核验价格、币种、运费、进口费用、税费、优惠条件、成色、库存、卖家、退货、保修、图片和评价
- 固定价和可直接购买的议价商品可以进入最低总价比较
- 拍卖当前价只作证据展示，不得冒充最终成交价或最低可购买总价
- 不同币种没有实时汇率证据时分开保留，不得直接混排
- 最终结论必须带检索时间、商品链接、覆盖范围、未知成本和风险提示

## 多轮搜索规则

默认执行精确型号最佳匹配、型号别名价格加运费升序、规格变体新上架三类轮次

达到最低三轮后，只有连续两轮新增稳定商品编号都不高于计划阈值时，才允许以饱和为理由提前停止

一次运行最多执行五轮且每轮只读取一页

预检、搜索和详情在同一个页面中串行读取，相邻自动动作至少间隔三秒

同一次运行已经取得的查询和详情证据保留十五分钟，重复请求优先复用

登录、人机检查、限流和宿主策略阻止出现后不自动重试

不使用验证码绕过、Cookie 导出、指纹伪装、代理轮换或隐身浏览器

详细规则见 `references/multi-round-collection.md`

## 访问预检

正式采集前必须使用目标查询完成一次真实搜索跳转

- `results-visible` 表示结果列表已经可见，可以进入多轮采集
- `no-results-visible` 表示页面明确显示没有结果，可以完成空结果研究
- 登录、验证码或人机验证需要用户操作时使用 `user-required`
- 宿主安全策略阻止页面时使用 `policy-blocked`
- 只能打开首页但无法搜索时使用 `fallback`
- 页面要求读取 Cookie、本地存储、设备指纹或浏览器配置时使用 `fatal`

`policy-blocked` 是硬停止，登录挑战和人机验证进入等待用户状态

这些状态不能通过更换浏览器、MCP 或其他后端绕过

## 后端使用顺序

1. 已经连接并获得用户授权的官方 eBay 读取接口
2. 已经安装、连接、审计并被用户信任的只读 eBay MCP
3. 受支持浏览器中的 eBay 官方网页

本仓库不会自动安装第三方 MCP，不会索取或保存 eBay 开发者密钥

每次运行只使用预检通过的一个后端，多轮搜索和详情核验不得在中途悄悄换源

所有后端必须返回相同 Schema

候选后端审计见 `references/backend-routing.md`

官方网页真实只读验证见 `references/live-validation.md`

## 证据和成本

- `A` 表示已经读取当前商品详情，并核验数字商品编号、直接价格、币种和至少一张商品图
- `B` 表示只读取当前 eBay 搜索卡片，可以进入候选池，不能成为最终最低价结论
- `C` 表示搜索摘要、转述或无法直接核验的信息，只能写入警告

最终赢家必须是 `A` 级证据

已知金额按 `商品价 + 运费 + 进口费用 + 税费 - 已核验优惠` 计算

优惠只有在详情页确认金额和适用条件时才允许扣除

`complete` 表示所有成本已知，`pre-tax-only` 表示税费未知，`display-only` 表示运费或进口费用仍未知

## 风险判断

卖家好评率低于 `98%`、反馈数量少于 `50`、不接受退货、卖家自行翻新、账户条件价格、页面矛盾和异常低价都会提高风险

综合风险为高的商品不能成为最终赢家

详细规则见 `references/risk-rules.md`

## 运行协议

只通过本目录的 Runner 执行任务

```bash
python3 scripts/runner.py start --input "<input.json>"
python3 scripts/runner.py advance --state-id "<state-id>"
python3 scripts/runner.py submit --state-id "<state-id>" --node-id "<node-id>" --output "<output.json>"
```

外部节点失败时使用 `runner.py fail`

`--kind` 只允许 `retryable`、`fallback`、`user-required`、`policy-blocked` 或 `fatal`

需要用户登录、完成验证码或其他人工动作时，让用户亲自操作，再调用 `resume`

```bash
python3 scripts/runner.py resume --state-id "<state-id>"
```

只有 Runner 返回 `status=completed` 时才报告完成
